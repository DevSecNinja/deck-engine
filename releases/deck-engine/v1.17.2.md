# @deckio/deck-engine v1.17.2

**Released:** 2026-05-18

## What changed

### Fixed

- **`<EditableList>` no longer overflows the slide.** v1.17.0 shipped the
  primitive with zero default layout CSS, so any slide that passed it a
  list without a wrapper `className` stacked items vertically in a bare
  flow column and ran off the fixed-height canvas. The harness changes
  in v1.17.1 made this far more visible because the agent now wraps
  every user-content `.map()` in `<EditableList>`. v1.17.2 ships a
  defensive `.deckio-editable-list` default class (a responsive
  `auto-fit minmax(220px, 1fr)` grid) that any naked list inherits.
  Slides that already pass their own `className` are unaffected.
- **Dev-only drag handle is now hover-only.** The reorder handle had the
  right structure (`.deckio-list-handle` button + sortable wiring) but
  shipped without any CSS rules, so it rendered as a default browser
  button — a chrome box on every list item, on every slide, all the
  time. Restored the original JSDoc intent: the handle is invisible
  and pointer-transparent until the item is hovered, the handle is
  keyboard-focused, or the item is actively being dragged. Keeps the
  slide surface clean while preserving the drag affordance and a11y.

### Changed

- Tightened `inline-editing.instructions.md`, `deck-add-slide/SKILL.md`,
  and the launcher's `system-prompt.md` to teach the agent that the
  list container must establish slide-aware layout — connecting the
  existing density limits table to `<EditableList>` and showing the
  recommended pattern (CSS module class + module rule). Documents the
  defensive default for callers who omit `className`.

## Upgrade guide

No code changes required. Bump and rebuild:

```sh
npm install @deckio/deck-engine@^1.17.2
```

Decks built between v1.17.0 and v1.17.1 that relied on the broken
"bare flow column" rendering of a naked `<EditableList>` will now
render as a responsive grid instead. If you want the vertical-column
look back, pass your own `className` with a flex/grid column rule.
Decks that already pass a `className` to every `<EditableList>` see
no visual change.

Pair with `deck-launcher` ≥ 0.2.1 for the matching system-prompt
update that teaches the in-product agent the same patterns.
