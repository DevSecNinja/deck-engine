# @deckio/deck-engine v1.20.0

**Export fidelity** — PDF/PPTX captures now match what you see on screen for
gradient-clipped headline text and progressive-disclosure slides, and custom
badges get the same overflow-safe breathing room as the built-in badge.

Both exporters share one capture path (`captureSlidePng`), so every fix below
applies to **PDF and PowerPoint** alike.

## What was wrong

1. **Gradient text exported invisible.** Headlines painted with
   `background: linear-gradient(...)` + `-webkit-background-clip: text` +
   transparent fill (a very common "gradient text" recipe) rasterized as fully
   transparent in some Chrome/`modern-screenshot` combinations, because the
   foreignObject renderer doesn't honor `background-clip: text`. The text simply
   vanished from the exported slide.
2. **Progressive-disclosure slides exported their pre-reveal state.** Step
   timelines reset to "nothing revealed" on slide activation and render
   non-revealed steps dimmed (`opacity: 0.15`). During export each slide is
   re-activated, so the capture caught the mostly-ghosted initial state instead
   of the fully-revealed slide.
3. **Custom badges could overflow on capture.** The export-mode breathing-room
   rule only targeted the built-in `[data-slot="badge"]`, so author-defined
   badge/pill/chip components (hashed CSS-module class names) could clip their
   own text under the export layout.

## Fix

- **Gradient-clipped text** is flattened to a solid color *before* capture and
  restored immediately after. The color is derived from the first gradient stop
  (falling back to the element's own color, then a provided fallback), detected
  from **computed style** so it works regardless of class name — including
  hashed CSS-module classes. New exported helpers:
  `parseFirstGradientColor` and `neutralizeClippedText`
  (`components/exportDeckService.js`).
- **Progressive disclosure** reveals everything during export via a new
  `useIsExporting()` / `isExportingNow()` signal (subscribes to the
  `data-export-mode` attribute the engine already sets on `<html>`).
  `GenericStepsSlide` renders all steps when exporting, and a CSS safety net
  (`html[data-export-mode="capture"] .deck-steps-step { opacity: 1 }`) catches
  any class-based disclosure even in decks that haven't re-scaffolded.
- **Badge breathing room** now also matches `[class*="badge" i]`, so custom
  badge/pill components get the same overflow-safe treatment as the built-in one.

## New public API

- `useIsExporting()` — React hook, `true` while a PDF/PPTX capture is running.
- `isExportingNow()` — imperative one-shot check.

Use these in any custom slide that reveals content over time so the export
captures the final state:

```jsx
import { useIsExporting } from '@deckio/deck-engine'
const exporting = useIsExporting()
const visible = exporting ? items.length : revealedCount
```

## Validation

- Engine test suite: **383 passing** (added unit coverage for
  `parseFirstGradientColor` and `neutralizeClippedText`, plus export-wiring
  assertions).
- Empirically validated with a Playwright capture harness against a real deck:
  gradient headline text exports visible (flattened to its first stop), all
  disclosure steps export fully revealed, and custom badges stay tidy — with the
  plain cover capture byte-identical (no regression).

## Known follow-up

Cover **logo drift** in some decks (logos sitting lower / touching the footer in
the export than in the live present view) is tracked separately. It reproduces
only with normal-flow / flex-anchored logos whose position depends on stage
height; absolute-positioned logos export correctly. Share the affected deck's
`CoverSlide.jsx` + `CoverSlide.module.css` for a precise, deck-safe fix.
