# @deckio/deck-engine v1.19.0

**Edit-mode UX polish + inline-edit save reliability.** Builds on the deterministic
slide hide/delete/reorder feature (1.18.0) with presentation-mode correctness, a
standalone fullscreen affordance, and two inline-edit save-reliability fixes.

## Slide edit tools & presentation mode

- **In-deck hide/delete tools** now live inside the top-right export group, share the
  export button's styling, and sit side-by-side instead of overlapping it. They reveal
  on pointer movement over the slide and fade out when idle, so they never get in the
  way while presenting.
- **Presentation slide count** (`x / y`) now counts only **visible** slides — hidden
  slides are excluded from both the index and the total via `displayIndex` /
  `visibleCount` on the `deck:slide` message.
- **Hidden-overlay flicker fixed** — the dimmed "hidden" treatment is now scoped to the
  current slide only, so it no longer lingers for ~1s when navigating away from a hidden
  slide.
- **Standalone fullscreen hides hidden slides** — when a deck runs standalone (outside
  the launcher) and the browser enters fullscreen, the effective mode switches to
  presentation so hidden slides are skipped automatically. New
  `resolveEffectiveMode(activeMode, isFullscreen)` helper drives this.

## Inline-edit save reliability

- **Rebase-and-retry on stale-base conflict (bug fix).** Saves send a whole-store base
  hash while the server merges per-field under a write lock. An unrelated concurrent save
  (e.g. picking a color in the toolbar, then pressing Enter on the same field) could
  return `409` and silently revert the just-typed text. The client now adopts the live
  hash from the `409` body and retries once, so per-field edits are last-write-wins and
  no longer get clobbered.
- **Auto-heal stale overrides against source (`base` facet).** Inline edits now record
  the source text they were made against (`base`). In dev preview, if the underlying JSX
  source later changes (e.g. an agent edits the slide), a stale text override is ignored
  and the fresh source wins — fixing the "inline edit vs. agent edit" divergence where an
  old override kept shadowing updated source. Styling overrides are preserved
  independently of text staleness. The facet is additive and backward-compatible:
  value-only entries still serialize as bare strings.

## Internal

- `EditableListSortable` drag-and-drop cleanup: removed dead drag-stomp guard and unused
  imports; the render prop now receives the live reordered items.

## Validation

- Engine test suite: **361 passing** (adds rebase-retry server contract test + `base`
  facet coverage across `isValidPatch` / `normalizeEntry` / `mergeEntry` / `serializeEntry`
  and middleware round-trip).
