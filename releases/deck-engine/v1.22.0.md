# @deckio/deck-engine v1.22.0

**Progressive disclosure, done right — and a real fix for "gradient text exports
blank."** This release ships the standard, export-safe disclosure hook
(`useDisclosure`), makes *existing* hand-rolled disclosure slides export
fully-revealed without touching their code, and fixes the actual root cause
behind invisible gradient-clipped **editable** headlines (e.g. the "Thank You"
title) in PPTX/PDF exports.

Both exporters share one capture path (`captureSlidePng`), so every fix applies
to **PDF and PowerPoint** alike.

## What was wrong

1. **Gradient-clipped *editable* text still exported invisible.** v1.20.0 added
   `neutralizeClippedText`, but the export-mode reset for inline-edit
   affordances used the `background` **shorthand**
   (`html[data-export-mode="capture"] .deckio-editable { background: transparent !important }`).
   The shorthand also resets `background-image` and `background-clip`, so a
   gradient-clipped `<Editable>` headline lost its gradient (→ nothing to paint)
   **and** fell back to `background-clip: border-box` — which made
   `neutralizeClippedText` no longer detect it as clipped text. Net result: the
   text-fill stayed transparent and the headline vanished. This hit the
   `GenericThankYouSlide` "Thank You" title and any gradient-clipped editable
   copy.
2. **Hand-rolled disclosure slides exported their pre-reveal (blank) state.**
   AI-scaffolded "click to reveal" slides commonly keep private `useState` step
   state and their own capture-phase `keydown` handler. They never learn that an
   export is running, so each captured slide sat at step 0 — exported empty.

## Fix

- **Gradient-clipped editable text** — the export-mode editable reset now clears
  only the hover/active **color** layer (`background-color: transparent`), so the
  gradient `background-image` and `background-clip: text` survive into capture
  and `neutralizeClippedText` flattens them to a solid color as intended.
- **Legacy disclosure slides** — during capture the exporter now *pumps* each
  slide to its final state (`revealDisclosureSteps`): it dispatches forward keys
  until the slide stops mutating, bounded and observed via `MutationObserver`.
  Slide navigation is suppressed while exporting (`isExportingNow()` guard in
  `SlideContext`) so an overshoot can't skip to the next slide. No edits to
  author slides required.

## New public API — `useDisclosure`

The blessed, export-safe way to build step-by-step / click-to-reveal slides.
It keeps key handling, navigation hand-off, and reset-on-exit in the engine —
and **auto-reveals during export**, so disclosure slides always capture their
final state with zero per-deck wiring.

```jsx
import { useDisclosure } from '@deckio/deck-engine'

const { step, isRevealed } = useDisclosure(items.length, { index })
items.map((it, i) => <Row className={isRevealed(i) ? 'in' : 'out'} />)
```

- Forward keys (→ / Space / PageDown / Enter) advance; ← / PageUp step back.
  Once everything is revealed, the next → bubbles up to navigate.
- Pass the slide's `index` so it only listens while active and resets on exit.
- `GenericStepsSlide` now dogfoods the hook as the reference implementation.

## New authoring guidance

- **Skill**: `deck-add-disclosure` — step-by-step workflow for adding (or fixing)
  a disclosure slide.
- **Instructions**: `progressive-disclosure.instructions.md` — the contract,
  patterns, and the anti-pattern (hand-rolled `useState` + `keydown`) that
  exports blank. Both auto-distribute to new decks via `create-deckio`.

## Validation

- Engine test suite: **721 passing** (added `useDisclosure` unit coverage,
  export-wiring assertions for the disclosure pump + nav suppression, a
  regression test pinning the editable reset to `background-color`, and
  skill/instructions guards).
- Empirically validated with a Playwright export harness against a real
  21-slide deck: progressive-disclosure slides export fully-revealed and the
  gradient-clipped "Thank You" headline exports visible.
